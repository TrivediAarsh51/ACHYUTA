# ACHYUTA Domain Glossary

## Purpose

This glossary defines the canonical terminology used by ACHYUTA.

These definitions should be treated as the authoritative terminology for architecture documents, software components, policies, APIs, and validation procedures.

---

## 1. Identity

A security principal under which a subject operates.

### Examples

* Local User
* Administrator
* SYSTEM
* Service Account

### Primary Question

> Who is associated with the request?

---

## 2. Subject

The active execution entity that initiates a security-relevant request.

### Examples

* Process
* Thread
* Service
* Driver
* Script
* Container

### Primary Question

> What is performing the action?

---

## 3. Request

A security-relevant operation initiated by a subject acting under an identity and attempting to perform an action against a resource within a specific context.

### Primary Question

> What is being requested right now?

### Conceptual Structure

```text
Request =
    Identity
    +
    Subject
    +
    Action
    +
    Resource
    +
    Context
    +
    Evidence
```

---

## 4. Action

The operation requested by the subject.

### Examples

* Read
* Write
* Execute
* Delete
* Create Process
* Load Driver
* Open Network Connection
* Modify Registry
* Access Memory

### Primary Question

> What operation is being attempted?

---

## 5. Resource

An object, service, capability, or system component that is the target of a request.

### Examples

* File
* Folder
* Registry Key
* Network Socket
* Process Memory
* LSASS
* Certificate
* Security Configuration

### Primary Question

> What is being accessed or modified?

---

## 6. Context

Environmental and situational information surrounding a request.

### Examples

* Time
* Network
* Location
* Device health
* Session
* Parent process
* User interaction
* Current trust state

### Primary Question

> Under what circumstances is the request occurring?

---

## 7. Evidence

A verifiable observation that reduces uncertainty about a security request.

### Examples

* Digital signature
* File hash
* TPM measurement
* Secure Boot state
* Sysmon event
* Defender detection
* Parent process
* Command line
* Authentication event

### Primary Questions

> What do we know that supports or contradicts the request?

---

## 8. Evidence Strength

An assessment of how strongly an evidence item contributes to confidence in a security decision.

Evidence strength is not equivalent to truth.

### Example Levels

```text
Very Low
Low
Medium
High
Very High
```

---

## 9. Policy

A declarative security rule defining conditions under which a request may be permitted, restricted, quarantined, or denied.

### Primary Question

> What security rule applies to this request?

Policies express security intent. They do not independently constitute the final decision.

---

## 10. Risk Assessment

An evaluation of the potential security impact associated with a request based on its characteristics, evidence, applicable policies, and context.

### Initial Levels

```text
Negligible
Low
Moderate
High
Critical
```

Risk assessment should not imply false numerical precision.

---

## 11. Trust State

The current security posture assigned during ACHYUTA's evaluation process.

### Initial Trust States

```text
Unknown
Observe
Verify
Restricted
Trusted
Elevated
Quarantined
Revoked
Denied
```

Trust is dynamic and may change as new evidence or context becomes available.

---

## 12. Decision

The result produced after evaluating a request against applicable evidence, policies, context, and risk.

### Initial Decisions

```text
Permit
Permit with Monitoring
Require Verification
Restrict
Quarantine
Deny
```

A Decision and Trust State are related but are not identical concepts.

---

## 13. Enforcement Action

The technical action used to implement a security decision.

### Example

* Allow execution
* Block execution
* Terminate process
* Restrict network access
* Isolate endpoint
* Require authentication
* Prevent access to resource
* Generate security alert

---

## 14. Telemetry Event

A recorded observation generated by the operating system, security control, application, or ACHYUTA component.

Telemetry is an input to evidence generation and continuous evaluation.

### Example

* Windows Event Log event
* Sysmon event
* Defender event
* Firewall event
* PowerShell event

---

## Terminology Rule

The terms defined in this document are canonical.

If implementation requires a new concept, the concept should be added to this glossary before being introduced as an architectural term.
